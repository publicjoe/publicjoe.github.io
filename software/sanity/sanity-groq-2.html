GROQ - Part 2

GROQ offers a number of Functions that will save you from needing to "post-process" data in your front end or API to shape data as desired from within the query.

Functions

For example, you can use the count() function to get the number of items in an array:

count(*[_type == "car"])

Coalesce

The coalesce() function acts as a fallback mechanism. It looks at a list of values you give it and returns the very first one that isn't null.

This is incredibly useful in Sanity because content creators sometimes leave optional fields blank, and you want to ensure your frontend always has something to display.

*[ _type == "event" ]{
  name,
  "displayTitle": coalesce(seoTitle, name, "Untitled Event"),
  "coverImage": coalesce(customImage, category->defaultImage)
}

In this example, the displayTitle field will first try to use the seoTitle. If that's null, it will fall back to the name. If that's also null, it will finally use the string "Untitled Event".

Similarly, for the coverImage, it will first try to use a customImage. If that's null, it will look up the defaultImage from the referenced category.

array::unique

The array::unique() function is used to remove duplicate values from an array. This is particularly useful when you want to ensure that your results are distinct.

array::unique(
  *[
    _type == "event" 
    && date > now() 
    && defined(headline)
  ].headline->name
)

In this example, we are fetching the names of all headlines for upcoming events and ensuring that the list of names is unique.

Custom Functions

You can reduce code duplication by creating custom functions in your GROQ queries.

fn learn::reference($doc) = $doc->{name};

*[_type == "event"]{
  "headline": learn::reference(headline),
  "venue": learn::reference(venue)
}

In this example, we define a custom function learn::reference($doc) that takes a document and returns its name. We then use this function to fetch the names of the headline and venue for each event.

For more information on custom functions, you can refer to the official documentation - Custom Functions Documentation

Joins and Subqueries

When a document contains a reference it only stores the ID of that document, GROQ can resolve it by using the -> operator to follow the reference and fetch the related document.

For example, if you have an event document that references a venue document, you can fetch the venue's name like this:

*[_type == "event" && defined(venue)][0]{
  name,
  venue->{
    name
  }
}

This query fetches the first single event that has a venue assigned to it, along with the names of both the event and that venue.

Here is the breakdown of how it works:

  1. The Filter & Selection (*[_type == "event" && defined(venue)][0])
    • _type == "event": Filters for documents where the type is event.
    • && defined(venue): Uses the defined() function to check that the venue field actually exists and is not null. This skips any events that don't have a venue set yet.
    • [0]: This is the slice operator. Instead of returning an array of matching events, it grabs only the very first matching document and returns it directly as a single object { ... }.
  2. The Projection ({ name, venue->{ name } })
    • name: Pulls the name of the event itself.
    • venue->{ name }: Uses the dereferencing operator (->) to follow the reference link stored in the venue field to the actual Venue document. From that linked venue document, it only pulls its name.

Reverse References

Sometimes you want to find all documents that reference a specific document. GROQ allows you to do this using the references() function.

For example, if you want to find all events that reference a specific venue, you can use the following query:

*[_type == "artist"][5]{ 
name,
"events": *[_type == "event" && references(^._id)]{
  name
}
}

In this example, we first fetch the 6th artist (index 5) and then use a subquery to find all events that reference that artist's ID. The ^._id syntax refers to the ID of the parent document (the artist in this case).

Sequential Projections

GROQ allows you to perform sequential projections, which means you can project fields from a referenced document and then further project fields from that referenced document.

For example, if you have an event that references a venue, and that venue references a city, you can fetch the event's name, the venue's name, and the city's name like this:

*[_type == "event" && defined(venue) && defined(headline)][0]{
  headline->{name},
  venue->{name}
} {
  ...,
  "title": headline.name + " at " + venue.name
}

In this example, we first fetch the event's headline and venue names, and then we create a new field called title that concatenates the headline name and venue name.

select()

The select() function allows you to conditionally choose values based on certain criteria. It works like a switch statement, where you can define multiple conditions and their corresponding values.

*[_type == "event"][0]{
  headline->{name},
  venue->{name}
} {
  "title": select(
    defined(headline.name) && defined(venue.name) => headline.name + " at " + venue.name,
    defined(headline.name) => headline.name,
    defined(venue.name) => venue.name,
    "Untitled event"
  )
}

In this example, we use select() to create a title field based on the availability of the headline and venue names. If both are defined, it concatenates them; if only one is defined, it uses that; and if neither is defined, it defaults to "Untitled event".

Dynamic Queries

GROQ allows you to create dynamic queries by using variables. You can define variables in your query and use them to filter or project data.

Static Parameters

Static parameters are predefined values that you can use in your queries. For example, you can define a static parameter for a specific event name:

// Query
*[
  _type == "event"
  && slug.current == $slug
][0]

// Parameters
{
  "slug": "the-national-at-the-bowery-ballroom"
}

In this example, we define a static parameter $slug and use it to filter events by their slug. The query will return the first event that matches the specified slug.

Dynamic Parameters

Dynamic parameters allow you to pass values into your queries at runtime. This is useful for creating more flexible and reusable queries.

// Query
*[
  _type == "event"
  && select(
    defined($date) => date > now(),
    true
  )
].name

// Parameters
{
  "date": "2025-07-04T06:44:33.014Z"
}

In this example, we use a dynamic parameter $date to filter events based on their date. If the $date parameter is defined, it will only return events that have a date greater than the current time. If the parameter is not defined (null), it will return all events.
