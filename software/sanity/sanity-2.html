Creating a Project

In order to create a Sanity project, you'll need a Sanity account. If you don't have one yet, you can create it here: Create Sanity Account

Within your IDE, you can set up a local development environment for Sanity. Run the following to create a new free project and Studio from the command line, change the name as you like.

pnpm create sanity@latest --template clean --create-project "Test App" --dataset production --typescript --output-path test-app/apps/studio

What each part does:

  • pnpm create sanity@latest - Uses PNPM to execute the latest version of the Sanity initialization tool to create a new project.
  • --template clean - Selects a minimal, empty template without any pre-built schemas or dummy data so you can build from scratch.
  • --create-project "Test App" - Bypasses the interactive prompt by automatically naming the new Sanity project "Test App".
  • --dataset production - Automatically sets up and targets a dataset named "production" for storing your content.
  • --typescript - Configures the Studio project to use TypeScript instead of plain JavaScript.
  • --output-path test-app/apps/studio - Specifies the exact folder directory where the Sanity Studio files should be generated.

Summary of what it does overall

This command silently scaffolds a brand-new, clean Sanity Studio project named Test App using TypeScript, sets up a production dataset, and places all the generated code inside the test test-app/apps/studio folder—all without asking you interactive setup questions.

The folder structure created in the command above should look something like this:

test-app/
  apps/
    studio/ <- This is where the Sanity Studio project is generated

Link to the documentation for more information - Sanity installation documentation

Run the Studio

To run the Sanity Studio locally, navigate to the apps/studio directory and execute the following command:

cd test-app/apps/studio
pnpm run dev

This command starts the Sanity Studio development server, allowing you to access the Studio in your web browser at http://localhost:3333.

About Studio

Sanity Studio uses Vite as its build tool to provide the ability to do rapid updates as the configuration changes.

Sanity Studio is built on top of React and provides a powerful editing experience for managing content in Sanity.

Open the Studio

Once the development server is running, you can open your web browser and navigate to http://localhost:3333 to access the Sanity Studio interface.

You will need to log in with your Sanity credentials to access the Studio. Go to sanity.io/manage to log in. Create an account if you don't have one.

Once logged in, you can start creating and managing your content within the Sanity Studio.

Configuration

Once you log in, you will see a screen that informs you that you have no document types defined.

Configuration takes place in the file apps/studio/sanity.config.ts. This file is the main configuration file for your Sanity Studio project. It defines the schema, plugins, and other settings that control how the Studio behaves.

Open the file apps/studio/sanity.config.ts to view and modify the configuration.

import {schemaTypes} from './schemaTypes'

export default defineConfig({
  // ...other configuration options...
  schema: {
    types: schemaTypes,
  },
})

In this file, you can see the schema types are import from apps/studio/schemaTypes/index.ts. Open this file.


export const schemaTypes = []

This file is where you define your content types (schemas) for your Sanity project.

Add Schema Types

You can add new schema definitions to this array to create different types of content.

The schema defines what document types and fields are visible to authors as part of the editorial experience. You define the structure (field descriptions, initial value, etc) and validation rules for each type. The schema is confined to a Studio workspace, not to the Sanity Content Lake dataset, which is considered "schemaless." Any JSON document can be stored in the Content Lake, as long as it has a value for the _type property.

When you create a new schema type, you'll need to define its structure and validation rules.

So let's get started by creating our first schema type. In the folder apps/studio/schemaTypes, create a new file for your schema type.

import {defineField, defineType} from 'sanity'

export const eventType = defineType({
  name: 'event',
  title: 'Event',
  type: 'document',
  fields: [
    defineField({
      name: 'name',
      type: 'string',
    }),
  ],
})

In this example, we define a new schema type called "event" with a single field called "name" of type "string".

defineType is a helper function that defines a new schema type definition.

defineField is a helper function that defines a new field within a schema type.

Next, we need to add this new schema type to the schemaTypes array in apps/studio/schemaTypes/index.ts.

import {eventType} from './eventType'
export const schemaTypes = [eventType]

Save the files and run the development server.

pnpm run dev

Now, when you open the Sanity Studio in your browser, you should see the new "Event" document type available for creating new documents.

name was defined as a string field, so you can enter any text value for the name of the event.

Add 2 more fields to the schema type:

  • date: a date field for the event date, it type will be datetime
  • venue: a text field for the event venue with type string

Types

Sanity provides a set of built-in types that you can use to define your schema. These types include:

  • string: A simple text string.
  • text: A longer text string, typically used for paragraphs.
  • block: A block of text, typically used for rich text content.
  • number: A numeric value.
  • boolean: A true/false value.
  • datetime: A date and time value.
  • image: An image asset.
  • file: A file asset.
  • reference: A reference to another document.
  • array: An array of values.
  • object: A nested object with its own fields.
  • slug: A URL-friendly string, often used for creating human-readable URLs.

For a complete list of available types and their usage, see the Sanity Schema Types documentation.

Reference Type

When defining a reference type, you specify the type of document you want to reference.

In the previous example, we defined the venue as a string field, what if we wanted to reference a venue type instead?

defineField({
  name: 'venue',
  type: 'reference',
  to: [{type: 'venue'}],
})

In this example, we define the venue field as a reference to a document of type "venue". This allows us to create a relationship between the event and the venue, enabling us to easily access the venue's details when working with the event document.

Array Type

When defining an array type, you specify the type of values that the array can contain.

For example, if we wanted to add an array of speakers to our event schema, we could define it like this:

defineField({
  name: 'speakers',
  type: 'array',
  of: [{type: 'reference', to: [{type: 'speaker'}]}],
})

In this example, we define the speakers field as an array of references to documents of type "speaker". This allows us to associate multiple speakers with an event, and easily access their details when working with the event document.

Block Type

The block type is used for rich text content, allowing you to create structured text with formatting, links, and other elements. You can define a block field like this:

defineField({
  name: 'description',
  type: 'array',
  of: [{type: 'block'}],
})

Deploying the Studio

Once you have your Sanity Studio set up and configured, you can deploy it to a hosting platform of your choice. Sanity provides a guide for deploying the Studio to various platforms, including Vercel, Netlify, and others. You can find the deployment guide here: Sanity Deployment Guide.

You can also deploy the Studio to Sanity's hosting platform. you can deploy it with the following command:

pnpm run deploy

Create a unique hostname for your Studio. Once the deployment is complete you can visit and share your sanity.studio URL.
