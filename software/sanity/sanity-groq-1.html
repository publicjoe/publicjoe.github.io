GROQ

GROQ (Graphical Query Language) is a powerful query language for fetching data from Sanity. It allows you to define complex queries and filter data based on various criteria.

For more information on GROQ, you can refer to the official documentation - GROQ Documentation

Here is an example of a GROQ query that fetches upcoming in-person events (this is part of the sanity.io training course):

*[
  _type == "event"
  && eventType == "in-person"
  && date > now()
]{
  name,
  headline->{
    name
  },
  "isUpcoming":true
}

The Filter (The *[...] section)

This part decides which documents to grab from your dataset. A document must match all three conditions to pass:

  • _type == "event": Only fetches documents where the document type is explicitly event.
  • && eventType == "in-person": Filters for events that are happening live/in-person (ignoring virtual or hybrid ones, for example).
  • && date > now(): Looks at a custom date field and compares it to the current timestamp (now()). This ensures you only get future events.

The Projection (The {...} section)

This part determines what data comes back for the matching events, acting like a filter for fields:

  • name: Returns the name field of the event directly.
  • headline->{ name }: The -> operator tells GROQ to follow a reference. It looks up a completely separate document ID stored in the headline field (like a speaker or headlining artist) and pulls just the name from that referenced document. You can think of this like a join.
  • "isUpcoming": true: This is a hardcoded alias. It creates a brand-new field in your API response called isUpcoming and sets its value to true for every single item returned.

Array Slicing

GROQ supports array slicing, which allows you to retrieve a subset of elements from an array field in your documents. You can specify the start and end indices to slice the array.

For example, if you have an array field called tags in your documents, you can use array slicing to get the first three tags:

tags[0...3]

This will return the first three elements of the tags array (indices 0, 1, and 2).

If we wanted to get to get the tags including the third one, then we can do this using just two dots instead:

tags[0..3]

This will return the first four elements of the tags array (indices 0, 1, 2, and 3).

For more information on array slicing and other GROQ features, you can refer to the official documentation - GROQ Documentation

Projection

Projection in GROQ allows you to specify which fields you want to retrieve from the documents that match your query. You can use the projection syntax to include or exclude specific fields.

For example, if you want to retrieve only the name and date fields from the matching documents, you can use the following projection:

{
  name,
  date
}

This will return only the name and date fields for each matching document, excluding all other fields.

For more information on projection and other GROQ features, you can refer to the official documentation - GROQ Documentation

Arbitrary Keys

GROQ allows you to create arbitrary keys in your projection, which can be useful for renaming fields or creating new fields based on existing data. You can use the following syntax to create an arbitrary key:

{
  "newKey": existingField
}

This will create a new field called newKey in the returned documents, and its value will be taken from the existingField. You can also use expressions and functions to compute the value of the new field based on existing data. For example:

{
  "formattedDate": dateTimeFormat(date, "YYYY-MM-DD")
}

This will create a new field called formattedDate in the returned documents, and its value will be the result of formatting the date field using the dateTimeFormat function with the specified format.

Pipe Operator

The pipe operator (|) in GROQ allows you to chain multiple operations together, making it easier to build complex queries. Each operation is applied to the result of the previous operation.

*[ _type == "article" ]| order(_createdAt desc)[0...10]

This will retrieve articles, filter them by type, order them by createddate in descending order, and then take the first 10 results.
